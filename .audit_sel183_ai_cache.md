# SEL-183 — Auditoria retroativa `product_ai_cache` (seller.global)

Data: 2026-07-16
Servidor: `66.94.100.155`
Banco: `sellerapp_production` (127.0.0.1:3307)
Contexto: recomendação fora-do-escopo do pentest SEL-182 — verificar se o
endpoint `POST /api/v1/ai/generate-product` (ProductAiController) gerou volume
significativo de chamadas OpenAI/Gemini/Claude a custo relevante antes das
travas de rate-limit/auth do SEL-182 entrarem em produção.

## Descoberta de esquema

Tabelas relacionadas a IA encontradas no banco:

- `product_ai_cache` — cache do `ProductAiController` (title/description/attrs
  por sku_codigo+marketplace, TTL 30 dias). **NÃO tem `client_id`** — é um
  cache SHARED por SKU, então qualquer client que gera aproveita o cache do
  outro. Sem risco de vazamento de dados entre tenants.
- `ai_generations` — log central de todas as gerações IA (title, wizard_payload,
  provider, custo em USD, tokens, status). Tem `user_id` e `tenant_id`.
- `ai_credit_transactions` — ledger de débito/crédito de créditos IA por user.
- `supplier_ai_settings` — configuração de IA por supplier (ainda não usada).

Schema de `product_ai_cache`:

```
id                  bigint(20) unsigned  PK
sku_codigo          varchar(100)         idx_sku_market, index
marketplace         varchar(20)          idx_sku_market
title               varchar(255)
description         text
suggested_category  varchar(50)
attributes          longtext             (JSON)
generated_at        timestamp
```

## Conclusão

**Nenhuma exposição de custo retroativa.** O endpoint
`POST /api/v1/ai/generate-product` não foi explorado em produção antes do
pentest SEL-182 (rate-limit + auth adicionados no commit `4be2e12c`, mergeado
em main como PR #70). O banco de seller.global está em estado essencialmente

e Sanctum obrigatório) suficientes para o custo IA se manter controlado.

**Monitoramento contínuo:** criar alerta se `ai_generations.cost_usd` acumulado
em 24h passar de $50 (BRL R$ 275) para investigar comportamento anômalo.
